# 写作包（Writing Pack）上下文装配与回写协议

本协议定义本地小说写作台如何把分散在文件夹里的设定、大纲、进度和写作规则，装成一个高命中率、不丢记忆的上下文包，交给任意桌面 Agent 或本机 CLI 执行。

## 一、三类标准创作动作

### 1. 生成下一章细纲（Outline）

装配顺序：

1. `00-总纲与世界观.md`（全文，锁死题材、红线与分卷目标）
2. `01-人物状态卡.md`（全文，锁死人物底色、OOC 红线与当前动态）
3. `02-伏笔与时间线.md`（重点标出「待回收」与近期到期伏笔）
4. `03-当前进度.md`（上一章结尾锚点 + 下一章写作备忘）
5. 上一章正文末尾 800 ~ 1200 字（承接语气与画面）
6. `_写作规则与Skill/` 目录下的用户自定义写作规则（如有）

输出要求：

- 给出 3~5 个场景节拍（含时间地点、出场人物、冲突推进与情绪落点）。
- 明确标注本章要回收或推进的伏笔编号。
- 不直接写完整正文，先让作者拍板方向。

### 2. 续写正文（Continue）

装配顺序：与「生成下一章细纲」相同，并额外附上作者刚确认的本章细纲。

输出要求：

- 只交付纯正文 Markdown，不输出思考过程或寒暄。
- 严格遵守人物 OOC 红线与用户的文风避雷项。
- 保持单章目标字数（默认 2500 ~ 3500 字）。

### 3. 润色当前章（Polish）

装配顺序：

1. 当前章全文
2. `00-总纲与世界观.md` 中的「文风与避雷」段落
3. `_写作规则与Skill/` 下的用户风格规则（如有）

输出要求：

- 只改表达、节奏与画面感，不擅自更改既定剧情走向或人物关系。
- 交付完整修订稿，放入预览区由作者决定是否替换。

## 二、写后回写规范（防止长篇吃书）

每定稿一章后，建议让 Agent 顺手做一次轻量回写，仅更新 3 处：

1. `01-人物状态卡.md`：只更新出场人物的「当前动态」，不动「性格底色与 OOC 红线」。
2. `02-伏笔与时间线.md`：补充本章新埋伏笔、把已回收伏笔标为「已回收」、追加时间线记录。
3. `03-当前进度.md`：推进最新章节号、更新「上一章结尾锚点」。
